# 01_data_analysis — EDA и сборка данных

Разведочный анализ истории прослушиваний: что слушается, когда, как
и из чего собрана коллекция. Сюда же входит сборка входных паркетов.

## Роль в проекте

**Вход:** готовые паркеты из `data/00_output/`. Собираются в `00_prep/` из сырых выгрузок Spotify.
**Выход:** понимание данных — до методологии и дашборда. Ноутбуки
ничего не пишут на диск, только показывают вывод.
**Потребители:** `02_methodology` (берёт примитивный PELT из
`03_eda_behavioral` как точку отсчёта), `03_dashboard` (использует
те же паркеты).

## Что внутри

**Сборка — `00_prep/`.** Четыре ноутбука, превращают сырые выгрузки
в 15 паркетов `data/00_output/`. Детали — в `00_prep/README.md`.

| # | Ноутбук | Задача |
|---|---|---|
| 00_0 | `00_0_orphans_detect.ipynb` | Находит сирот (слушалось, но ни в плейлист, ни в лайки), готовит CSV для загрузки в Spotify |
| 00_1 | `00_1_build_full_history.ipynb` | Собирает историю + аудио-фичи → 8 паркетов |
| 00_2 | `00_2_account_data.ipynb` | Парсит Account Data → 7 паркетов + обогащает `playlist_links` |
| 00_3 | `00_3_quality_check.ipynb` | Проверяет целостность всех паркетов |

**EDA — четыре ноутбука.** Каждый отвечает на свой вопрос.

| # | Ноутбук | Вопрос |
|---|---|---|
| 01 | `01_eda_basic.ipynb` | Что слушается — от масштаба до формы распределений |
| 02 | `02_eda_temporal.ipynb` | Когда слушается — ритм, тренды, аномалии |
| 03 | `03_eda_behavioral.ipynb` | Как устроено взаимодействие — сессии, сохранение, скипы, обсессии |
| 04 | `04_eda_playlists.ipynb` | Из чего собрана коллекция — структура, наполнение, ядро вкуса. Единственный EDA-ноут, где вызывается маскирование (`src.mask`) |

## Как работает

**Порядок.** Сначала `00_prep/`, потом четыре EDA.

**`01_eda_basic`.** Паспорт данных, `valid_play`, пять масок
(`All events`, `No skips`, `Core ≥3`, `Core ≥5`, `Deep dive`). Масштаб,
технологии доступа, топы (широта / глубина / lifespan), жанровый
профиль, совместные распределения, корреляции, экстремумы.
**Вывод:** звуковой профиль устойчив между фильтрами, единственное
содержательное различие — рост `instrumentalness` в осознанном
прослушивании.

**`02_eda_temporal`.** Четыре уровня: долгосрочный тренд, календарные
аномалии, ритмы, регулярность. Плюс три среза: платформы, треки-лидеры,
жанровая динамика.
**Вывод:** ритм устойчив по форме и переменчив по интенсивности.
2024 — единственный год, выделяющийся одновременно по аудио, времени
суток и регулярности.

**`03_eda_behavioral`.** Четыре уровня: сессии, сохранение, скипы
и навигация, обсессии. Плюс эволюция (Discovery, Retention, Burnout).
**Вывод:** профиль выраженного исследователя с высокой изменчивостью.
Discovery Rate 65.3%, Retention 35.5%, Burnout 32.3%, Variability
1.18 точек в год. Наивный PELT оставлен здесь как историческая точка
отсчёта для `02_methodology`.

**`04_eda_playlists`.** Четыре уровня: структура, содержание,
наполнение, ядро вкуса. Маскирование в блоке 0, до анализа.
**Вывод:** curated — единственный тип наполнения с заметной долей
в группе `active_listened`: 44% его плейлистов. У mass_import и batch
эта доля близка к нулю. Широта прослушивания различается в разы:
медиана 85.7% у curated против 10.4% у mass_import и 9.5% у batch.
Ядро вкуса — 1188 треков, KMeans k=2, Silhouette 0.215 (6 признаков
с tempo; финальная версия в `src/clustering/` — 0.264 на 5 признаках
без tempo, см. блок 9 ноутбука).

## Запуск

1. `00_prep/` отработал — 15 паркетов в `data/00_output/`.
2. Открыть EDA-ноутбуки по порядку: `01` → `02` → `03` → `04`.
3. Каждый читает `eda_ready.parquet` из `data/00_output/`. Ячейка 0
   сама находит `src/` вверх по дереву.
4. Ноутбуки ничего не пишут — только показывают вывод.

## Ограничения

- **N=1.** Всё, что здесь найдено — про один профиль. Никакие числа
  не переносятся на другие аккаунты без проверки.
- **Жанровый анализ ограничен долей `unknown`.** Пороги: 30% —
  предупреждение, 50% — выводы не делать. Проверка — `show_unknown_share`
  в каждом ноутбуке.
- **`03_eda_behavioral` содержит наивный PELT** (`pen=10`, 7 смешанных
  признаков). Оставлен намеренно — как точка отсчёта. В продакшн не идёт.
- **EDA — не источник истины по методологии.** Числа здесь описательные,
  не защищённые bootstrap/permutation. Для защищённых выводов —
  `02_methodology`.
- **Маскирование — только в `04_eda_playlists`.** Блок 0, до анализа.
  В `01_eda_basic`, `02_eda_temporal`, `03_eda_behavioral` вызова нет.
- **В `dashboard_data_prep.ipynb` маскирование тоже есть** — но это
  уже не EDA-слой.
